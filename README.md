# КП «Нейроюрист закрытого контура» · Лайфинтерактив

Одностраничное КП. Механика взята из КП Муар (реврилы, карусель, аккордеон, прогресс-бар),
стилистика — гос/юрист: графит-синий, золото, весы вместо логотипа.

**Файл:** `index.html` — правится напрямую, сборки не требует.
**Локальный просмотр:** `python3 serve.py` → http://localhost:8749/
**Живая версия:** https://ivannad11.github.io/kp-neuroyurist/

Именно `serve.py`, не `python3 -m http.server`: штатный сервер не отвечает на Range-запросы,
без них полоса прокрутки у роликов не работает. Проверка: `curl -D- -o /dev/null
-H "Range: bytes=100-999" http://localhost:8749/media/v01.mp4` должен вернуть **206**.
У самих `<video>` по той же причине стоит `preload="metadata"` — с `preload="none"`
браузер не знает длительность и не даёт перематывать даже при рабочем Range.

Цвета берутся из тех же `--d-*`, что и у `.dia`, но переменные объявлены на
`.shot--anim .shot-img` (светлый и тёмный варианты). Классы анимаций: `.aS` — подсветка
шага по очереди, `.aFlow` — бегущий пунктир связей, `.aScan` — сканирующая полоса,
`.aPop` — появление результата, `.aFill` — заполнение полосы, `.aSwap` — переезд метки.
Всё гасится в `prefers-reduced-motion`.

Базовая непрозрачность шагов — `.58`, не ниже: при `.3` схема 86 % цикла выглядела блёклой.
Тексты набраны мельче, чем в широких `.dia`-схемах, иначе карточка спорит с соседней схемой.

### Проверка текста

Глазами вылезающую строку в SVG не поймать — только скриптом, в iframe нужной ширины:

1. **Текст за `viewBox`** — `getBBox()` каждого `<text>` против `svg.viewBox.baseVal`.
2. **Текст за свой блок** — «свой» блок это тот `<rect>`, внутри которого текст *начинается*
   (`r.x <= b.x <= r.x+r.w`), из подходящих берём самый узкий. Иначе детектор цепляет
   соседний прямоугольник слева и сыплет ложными срабатываниями.
3. **HTML** — `scrollWidth > clientWidth` у листовых текстовых элементов, пропуская всё,
   что лежит внутри контейнера с `overflow-x:auto`.
4. **Обрезка по высоте** — `scrollHeight > clientHeight` у элементов с `overflow:hidden`.

Последняя проверка: 0 переполнений в 20 SVG и в HTML на 1280 и 390 px. Два класса
срабатываний — заведомо ложные: круглые кнопки `.playbtn` (текста нет, за границу выходит
декоративное кольцо `::before`) и секции с `overflow:hidden`, из которых торчит `div.glow`.

Слово «схема вместо ролика» из карточек **убрано намеренно**: заказчику это читается как
«продукт не готов», хотя сценарии помечены как работающие. Киккера «Схема» достаточно.

## Адаптив

Проверено на 320 / 360 / 390 / 430 / 768 / 1024 / 1440 px — горизонтального переполнения нет.
Широкие SVG-схемы и таблицы скроллятся вбок внутри своих контейнеров (`.dia-scroll`,
`.smx-wrap`, `.mt-wrap`), бегущие строки `.ticker-row` шире экрана намеренно.

Две поломки, которые чинились:

1. **Класс `.mt` был занят дважды** — таблицей приёмки (`min-width:620px`) и заголовками
   в медиа-слотах (`<b class="mt">`). Правило таблицы растягивало каждый заголовок до 620 px.
   Селекторы таблицы сужены до `table.mt`.
2. **`.rmi` распирался схемой.** У grid-элементов `min-width:auto`, поэтому SVG с
   `min-width:700px` растягивал весь блок «Пяти направлений» до 792 px при экране 390 —
   секция обрезала его по `overflow:hidden`. Добавлено `min-width:0` для `.rmi`, `.rmi>*`,
   `.rblocks`, `.dia`.

Проверять так: открыть страницу в iframe заданной ширины и сравнить
`getBoundingClientRect().width` каждого элемента с шириной вьюпорта. Обычный обход
`document.documentElement.scrollWidth` эти случаи **не ловит** — виновника прячет
`overflow:hidden` на секции.
